# 手机数据清洗、来源与更新规则

清洗版本：`4`。实现位于 `phone_assistant/cleaning.py`、`storage.py` 与 `import_legacy.py`。

本系统先保存来源提供的原始记录，再用确定性规则生成可查询字段。清洗只做有依据的单位转换、规范命名、配置归组和质量标记。缺失值、无法区分的多配置值、明确越界值保持 `null`，不调用 AI 补参数、猜售价或修补小数点。

## 数据链路

```text
ZOL 列表/系列的参考价 + 参数页原文 → 原始快照 → 自动清洗 → 按字段合并 → SQLite 规范手机记录
历史 Excel（只读）                  → 原始快照 → 自动清洗 → 历史字段补充 ↗
```

原始历史文件是 `data/recovered/phone_specs_export_中文表头.xlsx`，导入时不修改它。每个历史快照保留文件名、Excel 行号、原始中文字段和空值。日期单元格仅转成 ISO 字符串供 JSON 保存。

历史 Excel 没有逐条抓取时间或已核验的来源网址。因此历史记录的 `fetched_at` 和 `source_url` 为 `null`、`origin=legacy`、`availability=historical`；`legacy_source` 指向文件及行号。不能用 Excel 文件创建时间或机型发布日期代替抓取时间，也不根据产品 ID 构造一个尚未核验的网络来源。

新抓取记录的 `fetched_at` 是实际 UTC 抓取时刻；`release_date` 是原文给出的发布日期，两者独立。`listed` 需要爬虫在当前来源中取得上架依据，不能仅因最近抓取就把历史机型视为在售。

列表/系列提供的参考价保存在 `price`。参数页的 `电商报价` 只保留在原文，不能覆盖参考价。两者可能不同，且参考价也不代表用户当前可成交的价格。`price_source_url` 与 `specs_source_url` 分别记录价格和参数来源。

## 规范字段与转换

| 字段 | 依据与规则 |
|---|---|
| `brand` | 已知中英品牌别名统一；缺品牌时只从明确型号前缀识别，否则保持未知。 |
| `family_key` | 品牌及型号标准化，去掉明确的 RAM/存储容量括号后缀，供容量版本归组。保留 Pro、Ultra、Plus/`+` 等型号区别；原产品 ID、配置和快照不删除。 |
| `ram_gb` / `storage_gb` | TB×1024、MB÷1024、KB÷1048576 转 GB。旧列名明确标 GB 时允许裸数；来源未注明单位时不猜。 |
| `battery_mah` | Ah×1000 转 mAh。多个不同数值只在原文明示“典型值”时选取它，否则未知。 |
| `weight_g` / `thickness_mm` | kg×1000 转 g，cm×10 转 mm；不猜漏掉的小数点。 |
| `charging_w` / `refresh_hz` / `display_inches` | 识别 W、Hz、英寸等明确单位；旧 Excel 的单位列名可作为依据。 |
| `camera_mp` | 明确的主摄像素优先；旧摄像头结构优先主摄标签，否则保留来源的首个后置项。万像素÷100 转 MP。无法区分前后摄时保持未知，像素数量不等于画质。 |
| `soc` / `os` | 保留来源文字，只移除处理器字段的“更多/查看”等展示尾巴。 |
| `os_family` | 仅识别明文 Android/安卓、HarmonyOS/鸿蒙、iOS；其余记 `other` 或未知，不猜自有系统基底。 |
| `nfc` / `five_g` | 三态 `true/false/null`。明确否定优先；缺项和“暂无”保持未知。5G 否定仅针对 5G，不能把“不支持 CDMA”解释成不支持 5G。 |
| `release_date` / `release_year` / `release_month` | 完整合法日期转 ISO；仅知道年月时保留年份及整数月份（1–12），仅知道年份不补月份。`release_precision` 标明 day/month/year，不编造1日。 |

`12/16GB`、`256GB/512GB`、不同参考价范围等含多个配置的数据不会只取第一个数字。必须由来源明确到具体变体，才能得到单值。

参数标签查找允许 Unicode 规范化与空白差异，例如 `主 屏幕尺寸`、`主屏幕尺寸(英寸)`，以及明确的 `出厂系统内核` 别名；这只影响字段识别，原始标签和值仍完整保留。Apple 规格表的 `aria-rowspan` 表明下一行属于同一参数组时，继续读取该行；只有明确写着“两种机型均具备”的内容才同时应用于同页两个机型。Pro 与 Pro Max 的屏幕、重量及其他各自列出的值保持分开。官方显示屏中明确的最高刷新率、主摄像素、NFC 与 5G 按明文提取，不从品牌推断。

Apple 页面中的容量列表只证明提供这些容量，不代表某一个容量 SKU 的价格；续航小时不转成 mAh，所需电源适配器瓦数不转成手机充电功率。芯片名称取页面明确标出的型号，完整 CPU、GPU 描述保留在原文中。

ZOL 苹果具体配置的名称明确包含单一容量后缀（例如 `iPhone 18 Pro（2TB）`）时，使用这一 SKU 的容量标注，2TB 转为 2048GB。若系列共用的 `ROM容量` 行仍写 256GB，产生 `sku_storage_conflict` 质量提示并完整保留原参数，供购买前回源核验；不能把它无提示地显示成 256GB。规范容量的 `field_sources` 指向具体 SKU 身份来源及原时刻，共享 ROM 原文的 `specs_sources` 仍指向系列参数页；顾问也会收到冲突提示。规则只适用于该来源明确的唯一、末尾单一配置标注，多个容量括号、官网通用型号的多容量列表、含容量范围的型号名不会猜取某一容量，不靠型号数字推测容量。清洗重放不刷新 HTTP、价格或字段来源时间。

明确货币倍率会转换：`￥247.4万` 为 2474000 元，`2.5万元` 为 25000 元，不能忽略“万”误记为廉价机。屏幕原文明示“主:8.03英寸 副:6.53英寸”时，`display_inches` 保存主屏，副屏仍保留原文。`refresh_hz` 表示最高标称刷新率：`120Hz(1-120)` 或 `1-120Hz` 记录 120；这是同一屏幕的自适应范围，区别于多个容量配置，不声称始终运行在120Hz。

旧布尔清洗器曾将缺项压成 False，并可能把“不支持”中的“支持”误识别。因此历史 Excel 的 NFC `0/1` 原值仍保留在快照和原文中，规范 `nfc` 暂为 `null`，产生 `legacy_boolean_unverified`，等待当前原文核对。不能将旧布尔列“没有空值”当成完整、可靠的数据。

### 异常隔离范围

数值核验范围：RAM 0.000001–64 GB、存储 0.000001–8192 GB、电池 100–50000 mAh、有线充电 0.1–500 W、屏幕 0.5–15 英寸、刷新率 1–360 Hz、重量 10–1500 g、厚度 1–50 mm、像素 0.01–1000 MP。范围仅用于隔离待核验值，不代表官方硬件极限；升级规则后可以从原始快照重算。

参考价须大于零。大众品牌超过 **30000 元**时置 `price=null`，记 `price_outlier` 待回源核验；阈值为高端及折叠机留出空间。VERTU、8848 奢侈系列不应用这一大众阈值，允许保留高价。隔离不是宣判原值错误，更不会删除原值。未来真实产品跨过阈值，应核验来源并升级规则。

例如历史的一加 Ace 5 至尊版 59999 元暂隔离；VERTU 收藏限量机 2473990 元保留。诺基亚 G60 的 861mm 厚度和诺基亚 105 的 384GB RAM 置未知，不能自动猜成 8.61mm 或 384KB。

## SQLite、来源与合并

默认数据库为 `data/phones.sqlite3`：

- `import_batches`：导入批次和清洗版本。
- `raw_snapshots`：每次输入均追加保存，含来源、抓取时刻、保存时刻及完整原始 JSON。
- `phones`：每个产品 ID 的规范记录 JSON。
- `quality_issues`：快照、版本、字段、问题码、严重度和说明。

`Storage.import_many()` 在一个事务中写入批次、快照、规范记录和问题。缺 ID 等导致失败时整批回滚；不留下半批数据。没有覆盖或删除原始 Excel 的步骤。

合并按同一产品 ID、逐字段执行：有有效抓取时间的品牌官网原文优先，其次为有时间的 ZOL 原文，再次为未标时间的公开源原文，最后为历史 Excel。同一来源等级以较新抓取时刻为准；较旧输入只能补已有未知值。空值不能覆盖已有可用值。官网以 `origin=official` 标记，独立 ID 保留官网型号身份；跨来源相同型号按 `family_key` 归组，不删除 ZOL 的容量版本或价格证据。

官网起售价单独保存为 `price_from`，不能代替具体配置的 `price`，也不能借容量范围猜出起价对应的版本。`new_from_source` 与 `new_release_catalog_url` 记录新品/当前官方目录发现证据，不等于今年上市；年份、月份仍须从明确正文取得，版权年份、抓取时间和产品 ID 都不作为上市日期。新闻中取得的上市日期另存 `release_source_url` 与真实 `release_fetched_at`，不冒充规格页证据。

同一 `family_key` 的官网通用参数可提供给具体容量配置：处理器、系统、屏幕、最高刷新率、主摄像素、重量、厚度、NFC、5G、防护等级按明确且有核验时间的官网证据优先。每个字段保留官网真实来源及时间；与原 SKU 数据冲突时保留原值与冲突说明，不静默删除第三方原文。容量、RAM、价格、电池容量、充电功率不在共享范围，不能把另一版本的值复制过来。读取列表、单机详情、配置列表和比较时使用同一规则。

### 机型卡片与具体配置

页面按 `family_key` 展示机型，不按容量复制图卡。可选择的具体配置按真实 RAM、存储及有证据的网络版本去重；名称明确的 4G版、5G版或规范 `five_g` 字段用来区分网络，`false` 只表示非 5G，未知值保持未知。不能把相同容量的 4G、5G 版本当成来源副本合并。Pro、Pro Max、Plus 等不同型号不能互相合并。

同配置的来源副本依次优先：符合当前明确筛选条件、有独立近期报价、近期可信官网或 ZOL、有已知报价时价格较低、资料较完整、官网来源，最后按稳定 ID 选取。资料完整度只决定重复来源的入口，不评价手机好坏。主列表、完整搜索、发现区及配置菜单都使用这份最终集合，卡片默认从中取符合条件的最低已核价配置；其价格、RAM、存储和来源都属于同一个真实 ID，全部原记录仍保存在数据库。

官网多容量通用记录可由当前同网络版本的具体配置替代，不额外计成配置。若仅有历史具体配置，当前未知 RAM／容量／价格的资料仍保留自己的 ID 和空值；有独立近期报价的不完整 SKU 也保留，不借另一版本补 RAM 或价格。卡内网络标签可引用来源名称明确的网络版本，但不会将未知 `five_g` 改写为 `false`。

卡内的配置选择会加载该 SKU 的真实价格、参数及当前条件状态，详情、拖拽、比较、收藏和明确咨询均使用所选产品 ID。没有具体配置证据的型号仍显示型号资料，不能把容量列表拆成虚构的多条已核价记录。报价未知时明确标注，不能沿用上一个容量的报价。主筛选不计算推荐分。

同一 `family_key` 存在官网明确上市证据时，读取规范记录会核对 ZOL 年/月/日。明确冲突优先使用官网证据及其日期精度：官网只给 2026 年 9 月，不能把 ZOL 的 2025-09-21 改写成虚构的 2026-09-21。原 ZOL 日期保存为 `reported_release`，冲突保存在 `source_conflicts` 和质量提示，原始快照及 `specs` 不改写。年月一致时保留 ZOL 有证据的更精确日期；未知年月可由官网补充。同型号官网明确未来发售的版本会标为 `announced`，不进入已上市预算推荐。此核对在读取时执行，重算快照后仍生效，不跨配置复制价格。

- `field_sources` 为每个规范字段保存 `origin/source_url/fetched_at`。
- `specs_sources` 为每个原始中文参数保存同样的来源信息。
- 保留旧价格或旧参数时，也保留它们的旧来源和时间；不能把整条手机记录的新抓取时刻套到所有混合字段上。
- `specs` 保留原文；原参数页的同名空值不会清空旧原文。分析相机等配置时应优先读取非历史原文，避免把旧推测当作当前光学配置。

图片字段组单独合并：实际产品主图优先于型号目录图，再优先于系列缩略图；同角色比较来源明确的展示尺寸及采集证据，较新小缩略图不能覆盖主图。`image_source_url/image_fetched_at` 与价格和规格时刻分开。离线补图保存到独立 `image_overrides` 表，重清洗会保留并重新应用，不修改原快照或让价格变新。身份核验、角色与操作命令见 [图片采集规则](IMAGE_PIPELINE.md)。

`specs_fetched_at` 和 `price_fetched_at` 来自对应 HTTP 响应的保存元数据。命中缓存与恢复批次不会产生新的抓取时间；价格来源无时间时保留未知，不借参数页时间。首次重构发现并修正早期开发批次的处理时间误标：追加带 `_corrects_fetched_at` 的纠正快照，仅当产品、来源网址及被纠正时间均精确匹配时替换来源时间，原快照仍保留，重算可重放这次纠正。后续正常新抓取继续按实际响应时间合并。

`issues` 与 `quality_score` 属于最高优先级的最新输入快照；它们不等于逐字段合并后所有历史字段的完整问题集合。完整审计记录仍在 `quality_issues` 与 `raw_snapshots`。质量分是 18 个核心规范字段的有值比例，减去每条 error 的 4 分，范围 0–100；它衡量完整度和可解析性，**不保证来源事实正确，也不衡量手机好坏**。

`summary()` 的 `current_records` 表示最后已知状态为 listed；`fresh_records` 表示 ZOL 或官网抓取时刻在最近 30 天内，不能当作“最近发布的机型”。`official_records` 单独统计官网记录。历史记录、缺价、问题码、容量家族数量均另行统计。

清洗版本升级后调用 `Storage.reclean()`：按保存顺序重放全部原始快照，事务重建规范记录和来源，不追加重复原始快照。同时重建当前清洗版本的 `quality_issues`，消除同版本开发修正后的过期误报；其他版本的问题记录保留。任意失败会回滚，旧规范记录继续可用。
