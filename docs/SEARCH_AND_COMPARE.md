# 可选预算、完整型号搜索与多台比较

更新日期：2026-10-04。

预算不再是使用工作台的前置条件。首次预算为空、容量不限，可以立即浏览、搜索、查看资料与比较；需要控价或容量时再主动填写。比较不限制三台，参数表横向滚动，明确咨询的机型也完整交给顾问。

## iPhone 漏项的实际原因

修复前对本机数据库做了逐家族核对：121 条名称含 iPhone 的配置记录，47 个已有型号家族。即使最高预算填 50000 元，原推荐接口仍只返回 6 个家族；原新品发现只返回 3 个。这里的家族数包含旧来源的历史／未核验名称，不代表 47 款真实已上市或现在有库存的手机。

1. 搜索和购买推荐共用严格过滤。iPhone 16、16 Plus、16 Pro、16 Pro Max 等历史资料被隐藏；官网 iPhone 17 和 Air 因没有具体配置报价与容量无法进入推荐。默认 256GB 又额外排除了 128GB 或未知容量配置。
2. 新品补充也不能兜住普通目录。17 和 Air 的官网记录并不带本次新品标记，原 `new_from_source` 门槛让它们在两个入口都消失。
3. Apple 官方目录确实漏采一个入口。目录直接给出 [`/iphone-16/specs/`](https://www.apple.com.cn/iphone-16/specs/)，原发现规则只接受产品首页 URL，跳过了真实技术规格链接。修复后按真实 URL 直接采集，取得一条 iPhone 16 官方资料；页面只列单一型号，不据此补造 Plus。
4. 源站配置名与共享参数存在冲突。6 条 iPhone 18 Pro／Pro Max 的名称明确标 512GB、1TB 或 2TB，但 ROM 行都写 256GB，原清洗按该行生成错误容量。现在按明确单一 SKU 标注转换，并记录 `sku_storage_conflict`，保留原参数待回源核验。官网通用多容量列表保持未知，不猜某一容量或价格。

## 搜索与推荐的规则

`POST /api/recommend` 可以省略 `budget_max` 或传 `null`。零、负数、非数字和最高预算小于最低预算仍是输入错误。只设置预算下限时可保留下限，没有上限不会默认补成某个金额。

- `phones`：符合当前购买推荐条件的家族，仍检查上市状态、当前资料与独立报价时效；空预算不放宽事实证据。
- `catalogue`：输入型号搜索词后，返回完整已存匹配家族，不受推荐 60 项截断和新品标记限制。品牌、系统及用户明确选择的容量仍有效；预算用于提示，不让超预算型号消失。
- `catalogue_reasons / catalogue_codes`：解释历史、未来上市、价格未知、报价过期或超预算。`recommendation_eligible` 标明是否符合当前推荐条件，目录中的旧记录不获得虚假的购买推荐身份。
- `discovery`：保持来源明确的新机补充入口，不能替代完整型号搜索。

无预算时，预算余量的 10% 转给用途匹配：买新机用途 85%、时效 10%、品牌 5%；考虑二手机型用途 95%、品牌 5%。有预算时沿用原权重。具体来源报价不是成交价或库存；二手模式没有实际二手行情。完整公式见 [推荐策略](RECOMMENDATION_STRATEGY.md)。

## 多台比较与顾问

按钮及整个右栏拖拽都可连续加入，按 ID 去重。比较接口、面板列数、明确顾问目标和会话保存不截断到三台；未知参数继续显示待核实。没有主动选机时，顾问自动候选仍取前三台以控制上下文，这不限制用户自己加入比较的数量。模型的上下文和输出限制仍适用，不承诺一次回复能详尽评测任意规模的机型集合。

预算或搜索条件改变时重新请求，旧自动候选不会冒充当前条件结果；手动选中的比较机型可以保留，参数比较仍按当前条件重新读取并标注预算及资料状态。
