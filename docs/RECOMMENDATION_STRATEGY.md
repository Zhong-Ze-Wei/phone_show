# 推荐策略：先适合，再考虑新旧和品牌

生效日期：2026-10-04。默认排序从“新机优先”改为“综合推荐”，依据用户最新要求：推荐更适合用途与预算的机器，近一年和主流品牌适度加分。源码在 `phone_assistant/recommendation.py`。

## 入口与硬条件

页面初次预算为空，不暗用 4000 元。填写预算或主动点击预算档后才请求推荐；清空或重置后停止预算推荐。命令行 `recommend` 必须提供 `--budget`，API 必须提供 `budget_max`。

先检查品牌、系统、搜索词、容量、预算上下限、已上市状态和报价时效。默认只采用最近 30 天核验且来源标为在售的记录；没有具体配置价格不能用起价、零元或其他容量报价通过预算。未来发售机型保留在发现区，不能进入已上市推荐。旧机只因上市年龄较大不会被直接排除；抓取的新鲜度与上市的新旧是两个条件。

## 默认权重

| 分项 | 买新机 | 考虑二手机型 | 依据 |
| --- | ---: | ---: | --- |
| 用途匹配 `usage` | 75% | 85% | 现有日常、游戏、影像配置、续航与轻巧规格匹配；选中用途权重 3，其他用途 1 |
| 预算余量 `value` | 10% | 10% | `100 × (1 - 配置参考价 / 最高预算)`，结果限制在 0–100 |
| 上市时效 `recency` | 10% | 0% | 保守确认上市不超过 365 天为 100；366–730 天为 50；更旧或未知为 0 |
| 主流品牌偏好 `brand` | 5% | 5% | 策略名单内为 100，其他为 0；最多贡献 5 分 |

综合分等于四个 0–100 分项乘各自权重再相加，保留两位小数。用途分依旧返回 `score`，综合分返回 `recommendation_score`，卡片分别解释；`ranking_breakdown` 返回实际分项与权重，`ranking_reasons` 返回加分与待核实的说明。

预算余量只是同预算内少花钱的轻量偏好，不代表科学测得的性价比。用途占主要权重，因此便宜但配置不适合的手机不会仅凭低价胜过明显更适合的手机。近一年最多贡献 10 分，品牌最多贡献 5 分，也不能单独压倒用途差距。较老的强配置、好价机型仍可排在较新的弱配置机型前。

主流品牌采购名单：苹果、三星、华为、荣耀、小米、红米、OPPO、vivo、一加、realme、iQOO。名单包含几个品牌体系的子品牌，是可修改的产品策略；不以品牌名证明质量、可靠性、保修、售后覆盖或成片水平。用户主动限制品牌时仍以筛选为准，不补入其他品牌。

## 日期精度与边界

采用中国时间 UTC+08 的今天，以实际来源上市时间计年龄。完整日直接计算；只有年月时，实际日期属于当月区间；只有年份时属于全年区间。评分计算用该区间最早端对应的最大可能年龄，只有能保守确认近一年才获得完整近期分。区间跨过 365 天边界时不假定它是最新一天；若能确认在 730 天内，仅得次级分。

这些区间端点只用于计算，不写入 `release_date`；来源年月精度保持不变。未知上市时间不推断年龄，不用 `fetched_at`、型号数字或产品 ID 代替上市日期。明确未来日期和待上市状态始终排除。

## 二手机型参考的范围

选择“考虑二手”只取消上市年龄偏好，把 10% 转给用途。它不会自动启用 `include_history`、把历史价变成当前价、把新机价改成二手价，也不声称某机型存在二手库存。

当前官网与 ZOL 资料没有二手渠道成交价、成色、电池健康、维修史和保修证据；页面明确只能做机型参考。要确认二手预算和是否值得购买，需实际卖家报价与设备状况。历史资料另有用户主动选择的探索开关，旧价格始终带待核价说明。

## 其他排序与同型号版本

`recommended` 为默认综合分；`match` 只按用途匹配；`newest` 按真实上市年月日；`price_asc / price_desc` 按配置参考价。所有排序均先执行硬筛选，不能因新机、大品牌或低价跳过预算与资料条件。

同一型号家族只占一个位置，在当前排序下选符合条件的配置。独立“新机发现”仍允许看见超预算或待核价资料；发现卡有合格配置时选合适版本，全部超预算时选容量符合要求的较低近期报价，不能让未知价条目遮住已核价版本。

## 验证要求

测试覆盖近期加分、品牌轻量加分、旧强机胜过新弱机、低价不压倒用途、365/730 天和月年精度边界、未知日期无加分、二手模式不使用近期加分和过期报价、显式预算、排序枚举、硬预算与同家族版本选择。浏览器验证首屏空预算不发推荐请求，输入后才有结果，清空和重置不残留旧预算结果。

本轮完整验证：254 项 Python 测试、13 项前端测试通过。真实服务 60 个候选的综合分逐项符合公式；默认综合推荐、二手零时效权重、预算调整和原版工作台交互均已验收。推荐结果绑定请求条件签名，条件变更立即隐藏上一批结果；新请求延迟或失败时不会把旧候选当作当前推荐，也不把旧默认候选交给 AI。详情见 [界面核查与验收](UI_RESTORE.md)。
