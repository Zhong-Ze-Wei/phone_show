# 手机筛选策略

生效日期：2026-10-06。主页面只按明确条件筛选与排序，不计算综合推荐分、需求匹配分、品牌加分或上市时效加分。AI 分析由用户在右侧顾问或详情入口主动发起。沿用本文件名，使既有文档链接继续有效；2026-10-04 的加权策略已停止使用。

## 明确条件

首次打开预算为空、容量不限，可以立即浏览、搜索和比较。最高预算可省略或传 `budget_max: null`；零、负数和非数字是输入错误，不表示不限。只设置最低预算时也不补造价格上限。

主条件是品牌、系统、型号搜索、容量、预算上下限及资料范围。页面调用 `POST /api/filter`；旧 `POST /api/recommend` 使用同一个无评分筛选引擎，仅保留路径兼容。

- 默认浏览近期有来源标为在售、已有上市证据的资料。未知具体价格或报价过期不会在空预算时隐藏手机，卡片如实标注待核价。浏览结果不等于已经证明可按这个价格购买。
- 主动设置价格上限或下限后，只让有独立近期已核价的具体配置通过。未知价格不能以零元、官网起价或其他容量价格通过筛选。
- 资料与独立报价分别保留真实核验时间。历史或过期参考价不能冒充当前渠道价；主动启用历史资料也不改变这些时间。
- 不因大品牌、新款或猜测用途额外放行。图库不再只取加权排名前 60 个家族。

完整型号搜索与发现区保留历史、待上市、待核价或超预算资料，并说明不符合当前购买条件的原因。`recommendation_eligible` 是兼容字段，表示资格与证据状态，绝不是分数或产品质量结论。采集时间不证明手机刚刚上市，来源在售状态也不保证渠道库存。

## 排序与型号配置

仅提供三种明确排序：`newest` 按来源上市时间排列，`price_asc` 按配置参考价升序，`price_desc` 按配置参考价降序。默认使用 `newest`；日期或价格未知时排在有依据的记录之后。排序不评价产品好坏，不使用用途、品牌或规则分作隐藏权重。旧客户端的 `recommended`、`match` 兼容映射为 `newest`。

上市年月日保持来源精度，不把采集时间、手机名称或产品 ID 当作上市时间。不保存虚构的日；中国市场的日期边界使用 UTC+08。

同一 `family_key` 在图库中占一张卡，默认展示当前条件内参考价最低的真实配置，有已知价时优先于待核价版本。Pro、Pro Max、Plus、Air 等仍是独立型号。配置选择器保留实际 RAM／存储及明确的 4G／5G 版本；同配置重复来源去重，代表卡的真实 ID 必在菜单中。当前具体配置可替代同网络的无报价通用记录；若只有历史配置，当前待核验资料仍保留自己的 ID 和未知值，不借旧配置填 RAM 或价格。完整规则见 [清洗策略](CLEANING_STRATEGY.md#机型卡片与具体配置)。

切换配置后，价格、参数、来源、筛选提示、收藏、拖拽、详情和明确顾问目标使用该配置的真实 ID，图库按实际显示的所选配置重新排序。已经加入对比的旧配置继续保留，因此同型号不同容量可同时比较。选中的版本不继承代表卡的价格或条件资格。

## AI 分析单独进行

日常、游戏、拍照、续航等用途在右侧顾问中表达，只影响用户明确发送的分析，不改变图库或制造用途分。顾问读取规范事实、来源和筛选状态，结合用户问题解释取舍；缺少实测时不编造画质、发热、帧率、信号或续航结论。

打开顾问、选择角色、填写草稿和查看参数不调用模型。只有明确发送问题才调用 AIPing。明确咨询或比较的全部 ID 都交给顾问，不截断到三台；没有主动选机时，自动取当前条件中的前三台控制上下文，并标明这是资料候选而非评分前三名。

## 二手机型参考

“考虑二手”只表示选购场景，不把新机资料的参考价转换成二手行情，也不自动启用历史资料。现有来源没有二手成色、电池健康、维修史、保修或实时库存证据，需具体卖家报价和设备状况才能判断。

## 验证要求

验证应覆盖空预算浏览、明确金额约束与未知价、品牌／系统／容量、三种排序及旧枚举兼容、完整家族结果、配置独立来源和真实 ID，以及大于三台的比较。主筛选响应、卡片、预览、详情和对比均不得携带或显示旧规则分及加权解释。

改变主条件立即隐藏上一批结果并取消旧请求；新响应失败或延迟时不把旧候选当作当前结果。修改顾问用途不刷新图库，只有明确发送时才将其传入分析。搜索、配置和历史数据修复见 [搜索与比较说明](SEARCH_AND_COMPARE.md)；顾问的流式和来源规则见 [AI 顾问](AI_CHAT.md)。
