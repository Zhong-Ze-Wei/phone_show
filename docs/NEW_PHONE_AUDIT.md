# 新手机缺失问题核查与修复

核查日期：2026-10-04，中国时间。原来抓取的 715 条详情全部完成，并不表示最新品牌机型已覆盖。本次核查先检查数据库，再比对 ZOL 品牌页面、品牌官网目录及筛选规则。

后续交互与排序已根据用户偏好调整：预算首次留空，默认综合推荐，近一年和主流品牌适度加分，“新机优先”保留为手动排序。本文记录新品漏采修复时的结果；当前权重以 [推荐策略](RECOMMENDATION_STRATEGY.md) 为准，当前界面恢复依据见 [原版 UI 核查](UI_RESTORE.md)。

## 为什么一台都看不到

1. **发现入口漏采。** 原爬虫只解析主列表、网格和它们的分页。“按时间排序”的主列表仍可能陈旧。vivo 品牌页主列表没有 X500，但同一页面标题明确的“vivo手机新品”模块有 10 个真实 X500 配置链接，原解析器完全忽略了它。X500、Find X10、iPhone 18、Mate 90、Magic9 等因此没有进入原 715 条记录的采集队列。
2. **筛选会隐藏旗舰。** 原页面默认预算 4000 元、存储至少 256GB。有的新机已经在库，但参考价超预算、没有报价或容量不符合，不能进入预算推荐。界面没有独立的新品发现入口，用户无法区分漏采和筛选排除。
3. **排序和清洗不支持新机优先。** 原排序优先规格匹配分，旧款高配可能在新款前面；原日期清洗还会丢掉来源中的月份，仅保存年份。
4. **来源本身存在不一致。** ZOL 部分 X500 配置写 2025-09-21，官网参数给出 2026年9月；iPhone Duo 的发售日期也有冲突。不能仅刷新抓取时间就宣称资料准确。

## 修复后的流程

采集先核对五品牌官网公开目录，再动态发现 ZOL 品牌目录及标题明确的新品模块，之后抓对应详情和系列版本。型号来自正常源页面链接，代码不生成型号名称或猜测参数 URL。新品模块、主列表和官网目录的发现数、成功数、失败和待采项分别报告。

官网规格必须与请求产品的正文身份一致；HTTP 200 或正确 URL 都不能代替这个校验。Apple Pro/Pro Max 的同页列明确分别处理。vivo 平台中的 iQOO 手机保持 `brand=iQOO`、`platform=vivo`，不能因来源网站属于 vivo 而改变产品品牌。

规范数据保留真实上市年、月、日及精度。跨来源同型号的明确日期冲突按官网证据核对，原日期及原文保留；官网只有年月时不拼造具体日。明确未来发售的手机不会进入已上市推荐。具体容量价格、官网起价及未知报价分开保存，不能用起价让未知配置通过预算筛选。

新品漏采修复验收时，页面默认“新机优先”，后来按用户偏好改为默认“综合推荐”；仍可手动切换新机优先、需求匹配及价格排序。“新机发现”独立于预算推荐，允许看到超预算、价格或容量未知的手机，并说明排除原因、提供查看详情和主动放宽预算的操作。发现区为品牌概览，优先展示 vivo、OPPO、华为、荣耀、苹果各一个当前发现的代表机型；展开全部机型后按真实上市时间排序。品牌或型号筛选后不补入条件之外的机型。相同型号的发现卡优先选择符合当前条件的已核价版本；都超预算时优先符合容量要求的较低参考价。

## 实际结果

本轮定向补采发布 302 条来源记录：ZOL 新品模块 211 条、系列额外版本 30 条、官网 61 条型号/配置记录。五个重点品牌的 ZOL 新品模块各有 10 条可见记录，全部完成。与历史及前批资料合并后，数据库有 4428 条配置、2023 个型号家族、5777 个原始快照，清洗版本为 2。

| 系列 | 当前规范记录数 | 型号家族数 | 其中官网记录 |
| --- | ---: | ---: | ---: |
| vivo X500 | 25 | 3 | 15 |
| OPPO Find X10 | 13 | 3 | 3 |
| Apple iPhone 18 | 10 | 2 | 2 |
| 华为 Mate 90（含典藏版） | 18 | 5 | 4 |
| 荣耀 Magic9 | 14 | 3 | 3 |
| iPhone Duo | 5 | 1 | 1 |

表中是不同来源/容量的规范记录数，不是独立手机数量。iPhone Duo 的 5 条记录都按官网 2026-10-23 识别为待上市。iPhone 18 的多数配置暂未取得具体报价；只有源页明确的两个 2TB 配置有确定参考价，不用官网起价代替其他容量售价。

结果仍为 `partial`：16 个其他品牌的 ZOL 目录返回访问验证；官网初次限量采集后还有 226 个目录链接待采，不宣称全市场完整。官网目录数量包括旧机和不同产品入口，不能等同于缺少 226 款最新旗舰。范围和未解决项可在页面“数据质量”查看。

## 验证与维护

`npm run build` 与 `npm test` 通过：228 项 Python 测试、10 项前端测试。另离线重放 41 份真实官网规格页、61 条记录，全部通过身份校验；审计见 `data/reports/official_identity_audit.json`。原快照、真实响应时间及报价证据保持不变。

实际运行的 `http://127.0.0.1:8501/` 已通过浏览器验收：五品牌新机均能搜索到，预算不足时保留独立发现卡；主动放宽预算后进入推荐；同款版本的选择遵循容量和价格条件；iPhone Duo 被明确标为待上市。最终首页六张概览卡同时覆盖上述五品牌和 iQOO，展开的 105 款机型顺序与 API 上市时间顺序完全一致。390px 手机宽度无横向溢出，无 JavaScript 页面异常。验收截图和记录保存在 `logs/new-phones-overview-*`，该目录不进入发布包。

日常刷新使用页面“更新资料”或 `uv run phone-assistant sync`；仅补新机可使用 `uv run phone-assistant sync --latest`。`--resume` 接续批次，`clean` 从原始快照重放清洗。官网适配器支持按每品牌 offset 接续目录，详细合同见 [官方来源说明](SOURCE_COVERAGE.md)；具体清洗及冲突规则见 [清洗策略](CLEANING_STRATEGY.md)，实际批次与覆盖字段见 [采集流程](DATA_PIPELINE.md)。
