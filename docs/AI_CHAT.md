# AI 顾问与整栏拖拽

恢复日期：2026-10-04。原版截图不只是一个解释按钮：展开后是左侧手机列表、右侧聊天工作区，带角色、快捷问题、输入、清空、保存和加载入口。本轮依据真实截图和历史文档恢复这些业务功能，仍使用现有 React、FastAPI、SQLite 和 AIPing；没有取得或声称复用了缺失的旧前端源码。

## 当前筛选与分析分工（2026-10-06）

主页面是资料筛选与参数对比，不计算用途或综合推荐分。日常、游戏、拍照、续航等用途在右侧顾问表达，只影响明确发送的问题；设置用途、选择角色、打开面板都不会刷新图库或调用模型。模型收到规范事实、独立报价与字段来源，以及不符合当前条件的警告，不会收到旧规则分。没有手选时沿用当前筛选顺序中的前三台作为有限资料上下文，不能将其称为评分前三名。

## 使用流程

1. 桌面从手机卡片拖到**整个右栏**，包括预览、标题、空白处和展开后的聊天区，松手即可加入对比。数量不限，同一配置 ID 不重复；拖动取消会清除高亮。独立「+ 对比」按钮保留，触屏不必依靠拖拽。
2. 点击 AI 球打开顾问。普通桌面图库约占 70%，右栏约占 30%；聊天展开时左侧继续浏览手机，右侧约占 2/3。关闭后恢复原布局，不清空本次聊天。手机通过底部入口打开可关闭的聊天工作区。
3. 没有预算也可以打开、交流需求。只有明确发送消息才调用模型；打开面板、切换角色、点击快捷问题填入草稿、保存或加载均不调用模型。
4. 在主筛选或聊天区「最高预算」填写金额后，使用同一套筛选条件。修改预算或偏好会停止未完成回复、刷新候选，但保留聊天。消息里的金额不会擅自修改筛选；需要调整时由用户确认并填写。
5. 从详情明确点击咨询某台手机时，就讨论那台；从对比面板咨询时，完整讨论该组，不截断到三台。普通打开 AI 球时，已加入对比的机型优先，否则使用主动点选的预览或详情。增删对比或重新从球打开会恢复当前对比上下文。没有主动指定机型时，预算可以为空，自动取当前硬筛选后的前三台控制模型上下文；不假定 4000 元或其他金额。
6. 可以继续追问、停止回复或清空；「保存」手动把一份会话放在本浏览器，「加载」恢复文字及角色。加载不会恢复旧预算、筛选或对比栏，也不会把旧报价作为当前数据。

AI 球是点击入口，拖拽是加入对比；拖动时球让出鼠标事件，不遮挡整个右栏的投放。没有增加“拖进球即付费提问”的隐式动作。

## 五种角色

角色只改变说明角度，使用同一个模型、同一份规范记录和同一套硬筛选。

| 角色 | 说明角度 |
| --- | --- |
| 科技达人 | 芯片、显示、连接与配置差异，区分标称配置和实测表现 |
| 生活顾问 | 日常使用、体积重量、拍照配置与标称续航 |
| 性价比专家 | 已知参考价、用户预算、用途与配置取舍，不依赖固定评分 |
| 商务精英 | 系统兼容、办公场景、体积与标称续航，不编造认证或售后承诺 |
| 游戏玩家 | 已知芯片档位、内存和刷新率，不编造帧率、散热、功耗或跑分 |

历史文档确认了五种角色名称；后两种的具体旧描述未完整取得，当前职责根据手机选购目的明确实现。快捷问题只填入输入框，发送前仍可修改。

## 事实、历史和引用

- 每次发送重新读取 SQLite 的完整规范机型记录、字段来源和报价核验时间，不用卡片的精简字段冒充全部参数。
- 自动资料候选沿用 [筛选策略](RECOMMENDATION_STRATEGY.md) 的明确条件、上市证据与报价边界，不因聊天角色或自然语言放宽条件；不附综合分、匹配分或加权排名。
- 用户主动指定的超预算、历史、未上市或不符合筛选的手机可以讨论，但上下文附带警告和 `recommendation_eligible`，不能称作符合当前条件的购买推荐。
- 旧消息只解释指代和需求。当轮记录优先；聊天历史、原 Excel 和模型知识不能证明当前型号价格、库存或实测性能。未选到的具体机型资料不足时应重新选择。
- 每条回答保留它自己的候选快照与来源编号。模型收到和页面显示的是同一份完整当轮来源目录；后续回复重新编号，不能拿下一轮目录解释上一轮的 `[n]`。
- 默认不使用技术资料 RAG 代替当前行情；二手讨论继续明确没有二手价格、成色、电池健康、保修与库存证据。

## 接口与流式生命周期

`POST /api/chat`：

```json
{
  "message": "这几台日常使用怎么选？",
  "history": [
    {"role": "user", "content": "上一轮问题"},
    {"role": "assistant", "content": "上一轮已完成回答"}
  ],
  "selected_ids": [],
  "preferences": null,
  "persona": "tech"
}
```

`message` 为 1–1600 字；`history` 最多 12 条，只接受 user / assistant，每条最多 4000 字；`selected_ids` 没有三台上限，同 ID 去重后按原顺序全部读取。角色 ID 为 `tech`、`lifestyle`、`value`、`business`、`gaming`。`preferences` 使用 `/api/filter` 的筛选格式（旧 `/api/recommend` 仍兼容），最高预算可省略或为 `null`，表示没有价格上限；填写时必须大于零。整个 `preferences` 为空也使用无预算默认偏好。空问题、错误预算和不存在的机型在开始流前返回 4xx。

服务返回 `text/event-stream`，每个事件有 JSON `data`：

| 事件 | 作用 |
| --- | --- |
| `context` | 当轮机型、完整来源目录、角色及 selected / recommended / no_candidates 模式 |
| `delta` | 上游实际流返回的增量正文，页面即时追加 |
| `done` | 上游返回结束标记且正文非空；`finish_reason` 说明结束原因 |
| `error` | 安全中文错误；空正文、异常或没有结束标记的 EOF 均不伪造完成 |

每次发送只产生一次上游 `stream=True` 请求，关闭思考模式，输出上限 1800 token，不在失败后自动重试收费。调用方式依据 [AIPing 文本模型文档](https://aiping.cn/docs/API/text-models)。`/api/explain` 保持原接口，未被破坏。

停止、关闭、变更筛选或指定机型时，前端取消请求并隔离旧片段；后端在请求断开、等待 token 被取消或发送失败时关闭模型流及客户端。已经生成的 token 是否计费由平台决定。只有完整问答对进入模型历史，最多最近六对；每条送入历史最多 4000 字。取消、报错或长度截断的回复保留状态提示，不作为完整历史。取消不保证生成尚未开始，界面也不把局部正文标成已完成。

## 本地保存边界

会话保存在 `localStorage` 的 `pick-a-phone.chat.v1`，最多 40 条消息，整体 JSON 不超过 100 万字符；保存与加载采用相同大小、版本和字段类型校验。不会保存 API 密钥、筛选设置或自动发起模型请求。未完成回复不能经加载变成已完成事实。超大或不兼容数据显示错误，不能静默覆盖当前会话。

整栏拖拽只接收当前页面实际拖动的机型 ID 与自定义类型 `application/x-phone-assistant-phone`，普通文本、外来链接、已失效候选不能意外进入对比。加入操作集中去重、不限制三台，子元素进出不会让整个右栏错误地闪灭。参数表按机型数量扩展并横向滚动；无预算也可以比较。明确选择很多机型时会完整发送资料，上游模型仍有上下文及输出长度限制，回复中断或截断按既有错误状态展示，不暗中删掉机型。
